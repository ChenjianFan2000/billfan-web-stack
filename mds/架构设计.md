> 版本：v1.3

## 一、项目概述

面向单用户（≤3人）的私人学术论文管理系统，核心能力：

- 强认证保护的论文浏览与管理
- 上传 PDF 后全自动 AI 处理（元数据提取、摘要翻译、一句话概括、分类推荐）
- 自然语言 AI Agent，可操控数据库、搜索文献、阅读原文、解读系统日志
- Agent 聊天记录持久化，支持多会话管理（新建 / 切换 / 继续历史对话）
- 聊天框直接上传图片与 PDF，AI 智能路由处理（图片视觉理解 / PDF 提取答疑 / 一键入库）

## 二、技术栈总览

| 层次 | 选型 | 说明 |
|---|---|---|
| 反向代理 | **nginx** | 静态文件服务 + `/api/*` 转发 |
| 前端 | **React + Vite + Tailwind CSS** | 编译为纯静态文件，nginx 直接服务 |
| 后端 | **Python FastAPI + Uvicorn** | 单 worker，全异步，2 vCPU 足够 |
| 数据库 | **SQLite（WAL 模式）** | 单文件，零额外进程，百篇级别绰绰有余 |
| PDF 解析 | **PyMuPDF（fitz）** | 文字提取 + 页面图像渲染，纯 C 绑定，内存极低 |
| OCR 后备 | **Qwen Vision API** | 仅扫描版 PDF 触发，PyMuPDF 渲染图片后调用 |
| LLM 主力 | **Qwen API（qwen3.5-plus）** | 元数据提取 / 翻译 / 总结 / 分类推荐 / Agent |
| OCR 视觉 | **Qwen VL API（qwen-vl-plus）** | 同一 DashScope 账号，仅 OCR 分支使用 |
| 认证 | **JWT + httpOnly Cookie** | 会话持久，刷新免登录 |
| 任务队列 | **asyncio 后台任务 + SQLite 状态表** | 无 Redis，单用户并发极低 |
| 外部搜索 | **arXiv API + Exa API** | Agent 工具调用，非本地服务 |
| 导出 | **Python zipfile + 文本生成** | 标准库，零额外依赖 |

## 五、数据库设计

### 5.1 表结构

```sql
-- 用户表
CREATE TABLE users (
    id           INTEGER PRIMARY KEY,
    username     TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    created_at   TEXT DEFAULT (datetime('now'))
);

-- 分类表（支持一级嵌套）
CREATE TABLE categories (
    id           INTEGER PRIMARY KEY,
    name         TEXT NOT NULL,
    parent_id    INTEGER REFERENCES categories(id),
    order_index  INTEGER DEFAULT 0
);

-- 论文表
CREATE TABLE papers (
    id                  INTEGER PRIMARY KEY,
    title               TEXT,
    authors             TEXT,          -- JSON 数组字符串
    year                INTEGER,
    publisher           TEXT,
    doi                 TEXT,
    abstract_original   TEXT,          -- 原文摘要
    abstract_zh         TEXT,          -- 中文翻译（非中文论文填充）
    summary_one_line    TEXT,          -- 一句话概括
    category_id         INTEGER REFERENCES categories(id),
    file_path           TEXT,          -- /data/pdfs/xxx.pdf
    text_cache_path     TEXT,          -- /data/texts/xxx.txt
    created_at          TEXT DEFAULT (datetime('now'))
);

-- 处理任务状态表
CREATE TABLE processing_jobs (
    id           INTEGER PRIMARY KEY,
    paper_id     INTEGER REFERENCES papers(id),
    status       TEXT DEFAULT 'pending',  -- pending/processing/done/error
    error_msg    TEXT,
    created_at   TEXT DEFAULT (datetime('now')),
    updated_at   TEXT DEFAULT (datetime('now'))
);

-- 系统操作日志表（供 Agent 查询）
CREATE TABLE system_logs (
    id           INTEGER PRIMARY KEY,
    operation    TEXT NOT NULL,   -- upload/export/category_edit/paper_edit/agent_action/chat_file
    entity_type  TEXT,            -- paper/category/export_job/chat_attachment
    entity_id    INTEGER,
    detail       TEXT,            -- JSON，记录操作的详细参数和结果
    status       TEXT,            -- success/error/in_progress
    message      TEXT,            -- 人类可读的操作描述
    created_at   TEXT DEFAULT (datetime('now'))
);

-- Agent 聊天会话表
CREATE TABLE conversations (
    id           INTEGER PRIMARY KEY,
    title        TEXT NOT NULL,   -- 取首条用户消息前 30 字自动生成
    created_at   TEXT DEFAULT (datetime('now')),
    updated_at   TEXT DEFAULT (datetime('now'))
);

-- 聊天消息表
CREATE TABLE messages (
    id               INTEGER PRIMARY KEY,
    conversation_id  INTEGER NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    role             TEXT NOT NULL,    -- 'user' / 'assistant'
    content          TEXT,             -- 文字内容
    attachments      TEXT,             -- JSON 数组，引用 chat_attachments.id 列表
    created_at       TEXT DEFAULT (datetime('now'))
);

-- 聊天附件表（聊天框上传的图片与 PDF）
CREATE TABLE chat_attachments (
    id               INTEGER PRIMARY KEY,
    message_id       INTEGER REFERENCES messages(id) ON DELETE CASCADE,
    type             TEXT NOT NULL,    -- 'image' / 'pdf'
    file_path        TEXT NOT NULL,    -- /data/chat_files/{uuid}.{ext}
    text_cache       TEXT,             -- PDF 提取文字缓存（图片为 NULL）
    processed_data   TEXT,             -- JSON，PDF 完整处理结果（元数据+翻译+摘要+分类推荐），图片为 NULL
    paper_id         INTEGER REFERENCES papers(id),  -- 入库后关联，否则 NULL
    created_at       TEXT DEFAULT (datetime('now'))
);
```

### 5.2 索引

```sql
CREATE INDEX idx_papers_category ON papers(category_id);
CREATE INDEX idx_system_logs_operation ON system_logs(operation, created_at);
CREATE INDEX idx_processing_jobs_status ON processing_jobs(status);
CREATE INDEX idx_messages_conversation ON messages(conversation_id, created_at);
```

## 六、PDF 处理流水线

### 6.1 流程图

```
POST /api/upload
    │
    ├─ 保存 PDF → /data/pdfs/{uuid}.pdf
    ├─ papers 表写入占位记录（仅 file_path）
    ├─ processing_jobs 写入 status=pending
    └─ 触发 asyncio 后台任务（立即返回 job_id）

────────── 后台任务 ──────────

[Step 0] pypdf 内嵌元数据预提取（零 API 成本）
    ├── 读取 PDF 文件元数据字段：title / author / subject / creator
    ├── 字段存在且非空 → 记录为 hint，传入 Step 3 辅助 LLM 验证
    └── 字段为空       → 正常走 Step 3 全量提取，无影响
    （arXiv / IEEE / ACM 等正规来源论文通常有效，可减少 LLM 提取负担）

[Step 1] PyMuPDF + pdfplumber 双引擎提取
    ├── PyMuPDF：提取全文连续正文（速度快，适合段落文字）
    │       ├── 字符数 > 200 且乱码率 < 10% → 文字有效
    │       └── 否则 → 进入 Step 2（OCR 分支）
    │
    └── pdfplumber：同步扫描各页表格（仅对文字有效的 PDF 执行）
            ├── 检测到表格 → 转换为 Markdown 格式附加至文字末尾
            │       示例：| Method | Accuracy | F1 |
            │              |---------|----------|-----|
            └── 无表格   → 跳过，不影响流程
    合并产物：正文段落 + Markdown 表格 → 写入 /data/texts/{uuid}.txt

[Step 2] OCR 分支（扫描版 PDF）
    ├── PyMuPDF 将每页渲染为图片（内置，无需 Poppler）
    ├── 逐页调用 Qwen VL API（qwen-vl-plus）
    ├── 拼接各页文字结果
    └── 写入 /data/texts/{uuid}.txt → 进入 Step 3

[Step 3] 单次 Qwen API 调用（qwen3.5-plus）
    输入：
      - 论文全文（含 Markdown 表格，来自 texts 缓存）
      - Step 0 预提取的元数据 hint（如有）
      - 当前已有分类列表
    要求输出 JSON：
      {
        "title": "...",
        "authors": ["...", "..."],
        "year": 2023,
        "publisher": "...",
        "doi": "...",
        "abstract_original": "...",
        "abstract_zh": "...",       // 非中文论文才填充
        "summary_one_line": "...",  // 中文一句话概括
        "recommended_category": "..." // 从已有类目中选择
      }

[Step 4] 写入 SQLite papers 表
         更新 processing_jobs status=done
         写入 system_logs（operation=upload, status=success）

[异常处理] 任意步骤失败
         → processing_jobs status=error, error_msg 记录原因
         → system_logs status=error
```

### 6.2 前端进度感知

上传后前端持有 `job_id`，每 2 秒轮询 `GET /api/jobs/{job_id}`，收到 `done` 后刷新论文列表，收到 `error` 后展示错误信息。

## 七、AI Agent 子系统

### 7.1 架构

```
会话管理层（SQLite）
    conversations 表  ←→  messages 表  ←→  chat_attachments 表

POST /api/agent/conversations/{id}/chat  →  SSE 流式响应
    │
    ├─ 从 SQLite 加载该会话的完整历史消息（含附件引用）
    ├─ 处理本轮上传的附件（见 7.4 文件路由）
    ├─ 构建：系统提示词 + 工具定义 + 历史消息
    └─ Qwen tool use 多轮循环：
            用户消息（含附件内容）
               ↓
           Qwen 决策（调用哪些工具）
               ↓
           执行工具函数（本地 Python）
               ↓
           将工具结果喂回 Qwen
               ↓
           重复直到 Qwen 输出最终回复
               ↓
           持久化 assistant 消息到 SQLite
               ↓
           SSE 流式推送给前端
```

### 7.2 工具集（完整，共 11 个）

**数据库操作类（6个）**

| 工具 | 功能 |
|---|---|
| `list_categories()` | 获取所有分类及层级结构 |
| `list_papers(category_id?)` | 列出某分类（或全部）论文的基本信息 |
| `move_paper(paper_id, target_category_id)` | 将论文移动到指定分类 |
| `update_paper_info(paper_id, fields)` | 修改论文的任意字段（标题、作者、总结等） |
| `create_category(name, parent_id?)` | 新建分类 |
| `rename_category(category_id, new_name)` | 重命名分类 |

**外部搜索类（2个）**

| 工具 | 功能 |
|---|---|
| `search_arxiv(query, max_results?)` | 搜索 arXiv 获取新论文元数据 |
| `exa_search(query, max_results?)` | Exa 语义网络搜索 |

**论文内容读取类（1个）**

| 工具 | 功能 |
|---|---|
| `get_paper_fulltext(paper_ids: list)` | 读取 `/data/texts/` 中一篇或多篇论文的提取文字，用于内容答疑、深度对比、概念解释 |

> 支持多篇同时读取，适合"帮我比较这三篇论文的方法论差异"等场景。
> 单篇文字量大时自动截断至 token 预算上限，优先保留摘要与正文前段。

**系统日志查询类（1个）**

| 工具 | 功能 |
|---|---|
| `get_system_logs(operation?, last_n?, entity_id?)` | 查询系统操作日志，支持按操作类型、数量、关联实体筛选，用于解释"刚才发生了什么"、排查处理失败原因等 |

> `operation` 枚举值：`upload` / `export` / `category_edit` / `paper_edit` / `agent_action` / `chat_file`

**聊天附件入库类（1个）**

| 工具 | 功能 |
|---|---|
| `add_chat_pdf_to_library(attachment_id, category_id?)` | 将聊天框上传的 PDF 正式入库；处理结果已在上传时完成，此工具仅执行 DB 写入 + 文件复制，无额外 LLM 调用 |

### 7.3 系统日志写入规范

所有后端模块的重要操作均写入 `system_logs` 表：

```
写入时机                    operation 值        记录内容示例
──────────────────────────────────────────────────────────────
论文上传开始                upload              paper_id, 文件名
论文处理完成/失败            upload              耗时, 使用OCR与否, 错误信息
分类创建/重命名/删除         category_edit       操作类型, 旧名, 新名
论文手动编辑                 paper_edit          修改的字段及新值
导出任务开始/完成            export              导出类型, 包含论文数量
Agent 执行的工具调用         agent_action        工具名, 参数, 结果摘要
聊天附件处理                 chat_file           附件类型, 是否OCR, 是否入库
```

### 7.4 聊天框文件上传的智能路由

```
用户在聊天框附加文件并发送消息
    │
    ├─ 图片（jpg / png / webp 等）
    │       → 保存至 /data/chat_files/{uuid}.{ext}
    │       → base64 编码后作为 Qwen VL 图像消息内容
    │       → 写入 chat_attachments（type=image）
    │       → Agent 直接在上下文中"看见"图片内容
    │       → 可用于：截图答疑、论文图表解读、手写笔记识别等
    │
    └─ PDF
            → 保存至 /data/chat_files/{uuid}.pdf
            → 复用完整 PDF 处理流水线（与管理面板上传完全一致）：
                  [Step 1] PyMuPDF 提取文字（→ OCR 后备）
                  [Step 2] Qwen API 结构化提取：
                           标题 / 作者 / 年份 / 期刊 / DOI
                           摘要原文 / 摘要中文翻译
                           一句话概括 / 推荐分类
            → 所有结果写入 chat_attachments.text_cache + processed_data（JSON）
            → Agent 立即获得完整信息，可直接用于答疑、对比、讲解
            │
            └─ 若用户意图是"加入文献库"
                    → Agent 调用 add_chat_pdf_to_library(attachment_id)
                    → 读取 processed_data（无需重新调用 LLM）
                    → 写入 papers 表 + 复制文件至 /data/pdfs/ 和 /data/texts/
                    → chat_attachments.paper_id 更新为新论文 ID
```

**关键设计原则：** 聊天 PDF 与管理面板 PDF 走完全相同的处理流水线，所有信息在上传时即处理完毕。入库仅是一次轻量 DB 写入，无额外等待。Agent 根据用户意图（"帮我理解" vs "加入我的库"）自主决定是否调用入库工具。

## 十一、部署流程概要

```bash
# 1. 系统依赖
apt install nginx python3.11 python3-pip

# 2. Python 依赖
pip install fastapi uvicorn pymupdf pypdf pdfplumber \
            reportlab python-jose passlib sqlalchemy \
            dashscope httpx

npm install && npm run build  →  dist/ 产物

# 4. nginx 配置
server {
    listen 80;
    server_name billfan.cn;
    root /home/jcl/dist;

[Service]

Restart=always

certbot --nginx -d billfan.cn
```

## 十二、整体数据流汇总

```
用户操作
  │
  ├─[上传 PDF]
  │    → nginx → FastAPI(upload)
  │    → PyMuPDF 提取文字
  │    → [失败] PyMuPDF 渲染图片 → Qwen VL API OCR
  │    → Qwen API 结构化提取（元数据+翻译+概括+分类）
  │    → SQLite(papers) + SQLite(system_logs)
  │    ← 前端轮询 job 状态
  │
  ├─[浏览论文]
  │    → nginx → FastAPI(papers/categories)
  │    → SQLite 查询 → JSON → 前端渲染
  │
  ├─[Agent 对话]
  │    → nginx → FastAPI(agent)
  │    → 加载 conversations + messages（SQLite）
  │    → 处理附件：图片 base64 / PDF 文字提取
  │    → Qwen tool use 循环
  │         ├─ 工具执行 → SQLite / /data/texts/ / /data/chat_files/ / arXiv / Exa
  │         └─ system_logs 记录 agent_action / chat_file
  │    → 持久化本轮消息到 messages 表
  │    → SSE 流式 → 前端终端界面
  │
  └─[导出]
       → nginx → FastAPI(export)
       → SQLite 查询 + /data/pdfs/ 文件读取
       → zipfile 打包 / 参考文献文本生成
       → system_logs 记录 export
       ← 文件下载
```
